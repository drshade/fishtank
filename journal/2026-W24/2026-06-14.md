# 2026-06-14

## Shelly monitoring kit ordered — architecture settled (~€78)

Worked through the Shelly options and ordered the lot. Decision: the
**Shelly ecosystem handles sensors, leak, and control**; the **Pi shrinks
to camera-only** — the one job Shelly can't do. Everything integrates with
the existing Gen4 strips and the Shelly app (no Home Assistant).

Ordered:
- **BLU RC Button 4 ZB** (€19.24) — 4-button desk remote, phone-free
  control of strip sockets. Pair in **Bluetooth mode** (any button ×4 →
  blue LED); ignore the Zigbee side. Strips are the BLE gateway. CR2032,
  ~2yr. Chosen over the single BLU Button1 (4 discrete buttons beat
  memorising click-patterns).
- **BLU H&T Display ZB Black** (€25.41) — ambient air temp/humidity +
  light sensor + e-ink readout. BLE via strip gateway, ~2yr battery.
  Chosen over the **H&T Gen3**, whose poor reviews trace to WiFi battery
  drain; BLE sidesteps that. The light sensor doubles as a photoperiod
  cross-check.
- **The Pill** (€9.98) + **DS18B20 3.5mm waterproof probe** (€4.11) —
  Shelly-native water temp, scriptable. USB-C powered.
- **Flood S Gen4** (€19.24) — leak sensor for the cabinet floor under the
  canister. A finished product beats the original DIY Pi moisture probe;
  covers the below-waterline siphon risk taken on 2026-05-26.

Why Shelly over the original Pi-centric plan (journal 2026-06-12):
per-socket **power monitoring is native to the strips and impossible on
the Pi**; leak/ambient/control are better as finished devices; one app,
no hub. So the Pi is now justified by the camera alone.

## Monitoring architecture (for when it lands)

- **Equipment-failure alarm**: Shelly Script on the strip watches the
  canister socket's active power → push on dropout. Directly mitigates the
  canister single-point-of-failure (stall → no flow → no aeration →
  pre-dawn O2 crash). Catches **total power loss, not** an airlock/partial
  clog (motor still spins, power unchanged) — safety net, not a flow
  guarantee.
- **Heater duty / stuck-heater**: heater socket power is a clean on/off
  signal; alarm on continuous draw when it shouldn't fire (heatwave cook
  risk, exactly the heatwave-protocol fear).
- **Data logging**: Shelly app auto-logs temp/humidity/water-temp (free
  tier hourly, CSV export). Keeps the manual `measurements.csv` for the
  chemistry the sensors can't read (GH/KH/pH/ammonia).
- **Future automated extraction**: Pi cron → Shelly Cloud Control API (v2;
  or local RPC for the WiFi devices) → pull readings, compute 24h
  min/max/current locally → append `data/shelly-log.csv` → commit + push.
  No documented sensor-history API endpoint, so poll-and-compute (fine for
  slow-moving tank temps). **Auth key must stay out of the repo.**
